# Site template playbook

How every client website is created, protected and released. Claude reads this file at the
start of each session in this repo. Edit it (or ask Claude to) to change the rules.

Status: the Astro template, `scripts/new-site.sh` and the `new-site`, `release` and
`expire-preview` skills are written. `scripts/new-site.sh` has not been run for real yet, and
nothing has been deployed to Netlify from this template, so the password page is tested only
locally with `netlify dev`.

## Accounts and identity

- Netlify: one team for every site, on the **Personal** plan: about $9 a month for 1,000

## Branches and deploys

```
feature branch (big features only)  ->  dev (preview)  ->  main (live)
```

- Day-to-day work goes straight on `dev`. Use a feature branch only for a big feature.
- `main` is the live site and changes only when the owner says "release": merge `dev` into
  `main` once and say it costs one deploy.
- On sites with client editing, `main` also takes the client's published edits. So a release
  first merges `main` into `dev` (never the other way round without it), so it never
  overwrites the client's changes. See the `release` skill.
- Never force-push or delete `main`. The free plan cannot enforce this on private repos, so
  it is a rule for Claude and the owner.
- Follow the `netlify-credits` skill in each repo.

## Repo safety checklist (every new repo)

- Private, default branch `main`, `dev` branch created.
- Dependabot alerts and security updates on.
- `.gitignore` covers `.env*`; secrets live only in Netlify environment variables.
- Local secret check before each commit (`.githooks/pre-commit`, switched on per clone by
  the new-site script; cloud sessions do not have it).
- Local git identity set (see above).
- Delete merged `claude/` branches after merging.

## Prospect previews

The preview site is the sales pitch, so it is fully set up from the first push to `dev`:

- Password page in front of the site, and `noindex`.
- Unlocking the password page sends the owner a cookie-free "preview opened" notification.
  It posts to the address in the `PREVIEW_NOTIFY_URL` environment variable: an ntfy topic the
  owner's phone is subscribed to. The address is kept in `~/.config/site-template/env` on the
  owner's Mac, never in a repo, and `scripts/new-site.sh` copies it into each Netlify project.
- Each preview's password is generated by the script and saved in
  `~/.config/site-template/sites/<site>.env`. Never print it in chat.
- While a site is a preview, production builds are skipped, so previews cost no credits.
  Prospects are sent the `dev` address.
- Microsoft Clarity loads only after the visitor accepts the cookie banner. Previews share
  one Clarity project called "Previews", tagged with the business name.
  Previews Clarity ID: `yx1cctzktd`
- A client gets their own Clarity project when they sign.
- "Expire preview" swaps the site for a "preview no longer available" page.

## Sections and add-ons

- Default sections: Home, Who we are, Get in touch, WhatsApp button, cookie banner,
  cookie policy.
- Add-ons, each with an on/off switch and a demo mode in the site config: booking
  (Calendly or Cal.com style), calendar, shop, quote wizard, booking request form, price
  list, gallery, Google reviews and map, Instagram feed, newsletter, multi-language.
- Demo mode looks and clicks like the real thing with sample data; nothing is sent or
  charged. Going live means swapping in the client's real account.
- Keep editable content (prices, photos, events, hours) in data files under `content/`,
  never in code or `site.config.ts`, so a CMS can edit it.

## Client editing

Clients change small things themselves; the owner keeps design and code. Follow the
`client-editing` skill. The kit is in `client-editing/`: `README.md` (diagrams of the cycle,
the owner's setup checklist, troubleshooting), the shared `publish.mts` function, an example
`.pages.yml` and the client guide template. In short:

- Pages CMS (free, `.pages.yml`) with strict forms. Clients are invited by email and need no
  GitHub account. They save to an `edits` branch, whose preview
  (`https://edits--<site>.netlify.app`) is a free branch deploy; add `edits` to the branch
  deploys in Netlify.
- A password-protected `/publish` page and Netlify function merge `edits` into `main`
  through the GitHub API, capped at 10 publishes a month (`PUBLISH_CAP`, counted in Netlify
  Blobs). On a conflict it never forces and says "Ask Over a Brew to publish this one".
- Netlify environment variables: `PUBLISH_PASSWORD`, and `GITHUB_TOKEN` (fine-grained, that
  one repo only, Contents read and write). The owner pastes the token into Netlify; never in
  code or chat.
- Each publish is one production deploy: 10 publishes is 150 of the 1,000 monthly credits.
  Count that per site when deciding how many client sites one team can carry, or host a
  client on their own Netlify account.
- A client guide goes in each site's `docs/editing-your-site.md`.
- First built on `rolling-spanner` (October 2026).

## Shared files

Three files are the same on every site, whatever it is built with. The one source is this
repo; `scripts/sync-shared.sh <site-clone> [public-dir]` copies them into another site.
Never edit the copies.

- `public/site-kit.js`: cookie banner, Clarity loader (only after Accept) and the WhatsApp
  button. Loaded with one script tag; configured with `data-` attributes.
- `netlify/edge-functions/preview-gate.ts`: the password page and "preview expired" page.
- `netlify/preview.config.ts`: per-site settings for the gate (created once, then owned by
  the site). `scope: 'previews'` locks only preview addresses and never the live site.
- `client-editing/publish.mts`: the client's Publish button, for sites with client editing.
  Copied to the site's `netlify/functions/publish.mts`; configured by environment variables.

Netlify's own team-login protection is switched on for preview deploys on this team
(`sso_login`, non-production). Only people logged in to the Netlify team get past it, so it
must be off on any site whose preview a prospect needs to open with a password.
